# AI DEV DIRECTOR v4 목표 정의서 (2026-11-06, 헤이데이 대표 지시)

## 한 줄 목표
대표가 「○○ 같은 앱 만들자」 한 줄을 말하면, AI 팀이 기획 → 디자인 판단 → 구현 → 실제 화면 확인 → 수정 → 문서·출시 준비까지 끝낸다.
대표는 세 번만 개입한다: ① 기획 확인 ② 중간 화면 확인 ③ 출시 승인.

## 왜
- 지금(0.3.7)은 「코드 짜기 → 테스트 → 다른 AI 검수」 구간만 자동이다. 그 앞(기획)과 뒤(화면 확인·다듬기·문서)는 사람이 한다
- 실제 비교 대상: 대표가 Claude와 대화로 만든 데스크탑 앱 「DAYZ」. 기획·디자인 판단·화면 점검·출시를 대화로 반복했다
- v4는 그 대화형 과정을 프로그램 안의 단계로 옮긴다

## 대표가 체감할 결과
1. 한 줄 입력 → 10분 안에 「기획서(화면 목록·기능·데이터·디자인 방향)」와 화면 뼈대 그림이 나온다. 대표는 고칠 점을 말하거나 승인한다
2. 승인 뒤에는 수십 단계 마일스톤으로 끝까지 간다. 중간에 끊겨도 이어서 간다
3. 단계마다 실제 앱을 띄워 화면을 캡처하고, AI가 「깨짐·겹침·작은 글자·빈 화면·콘솔 오류」를 판정해 스스로 고친다
4. 몇 단계마다 캡처를 붙인 진행 보고가 HUD에 뜬다. 대표가 「이건 별로」라고 하면 방향을 고친다
5. 끝나면 실행 방법·기능 설명 문서와 출시용 묶음(웹은 정적 배포본, 데스크탑은 앱 묶음)이 나온다. 출시·배포·결제·계정은 대표 승인 뒤에만 한다

## 지켜야 할 것(기존 규칙 유지)
- 종량제 API 금지. 로그인된 구독 CLI(claude, codex, grok, agy)만 쓴다
- 원본 프로젝트는 격리 작업본에서만 고친다. 사람이 그 사이 고친 파일은 덮어쓰지 않는다
- 돈·실계정·되돌릴 수 없는 외부 행동은 사람에게 묻는다
- 검수는 fail-closed. 증거가 없으면 통과가 아니다
- GPL·AGPL 코드는 가져오지 않는다(생각만 참고). MIT·Apache·BSD만 이식한다
- 대표 취향 기준(흰 바탕 기본·큰 글자·화면 문구 마침표 금지·AI 티 금지 등)을 「취향 규칙 파일」로 넣고, 기획·검수가 그 기준을 쓴다

## 성공 기준(첫 시험)
- 시험 과제: 「동네 조기축구 출석·회비 관리 웹앱 만들어줘」 한 줄
- 대표 개입 3회 이하, 4시간 안에 실행되는 앱 + 문서
- 화면 점검: 주요 화면 5개 이상 캡처, 겹침·넘침·12px 미만 글자·콘솔 오류 0건
- 테스트와 독립 검수 통과, 다시 실행해도 같은 결과

- 여러 사용자 동시 사용(지금은 대표 맥 한 대)
